# 运营逻辑与亏本原因梳理

> 说明：本文只基于当前年度在线策略结果和 4.8 生命周期重算做整理，数值均为模型仿真输出，参数仍属公开代理或假设值。

## 1. 这套模型怎么运转

1. 调度层用 6h 滚动先验-后验策略，只执行首小时。
2. 每小时只继承上一小时末的 BESS、氢库存、电解槽和算力状态，不做事件前重置。
3. 目标函数不是“利润最大化”，而是
   `economicNetCostCNY = operatingCost - outputRevenue + terminalAdjustment`。
4. 约束优先级里，可靠性和储备约束优先于纯经济性；若零ENS不可行，则进入最小ENS层级并记录放宽原因。
5. 计算负荷被改成可中断柔性负荷，`pComputeBaseDemandMW` 在年度场景里被置零。

## 3. 为什么项目层面仍然亏

1. 运行层是赚钱的，但生命周期层要把 CAPEX、固定 O&M、替换和融资一起算。
2. 4.8 重算里，年折旧约 11.883 亿元，年融资成本约 15.878 亿元，年固定运维约 8.367 亿元，年替换准备金约 4.402 亿元。
3. 这些年化资本和固定成本加起来仍显著高于 13.1247 亿元的现金运行毛收益，所以项目层净值为负。
4. 资产盘子太重：800 MW 源侧、100 MW 电解槽、120 MW 算力、200 MW 海缆/站端、80 MW/160 MWh BESS 全都保留，但利用率并不高。
5. 计算和氢的收入依赖公开锚价和假设价，不是已签合同价；其中氢库存终值只是期末估值，不是当年现金回款。
6. 策略本身还带有储备和可靠性优先约束，计划回退 359 h、储备目标回退 316 h、可靠性最小ENS层级启用 154 h，说明它不是纯粹的利润最大化调度，也不能写成年度零缺供。

## 4. 结论

结论很直接：当前模型的“运营”不亏，亏的是“投资”。  
要让它从项目层面转正，关键不在再压一点运行成本，而在于重新校准资产规模、合同价格、固定运维和利用率。
